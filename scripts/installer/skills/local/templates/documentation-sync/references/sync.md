# Sync mode

The default path: a change touched documented behavior, or a page is being edited directly.

Apply the gate first — most code changes need no doc change, and saying so is a complete
outcome. Only when a reader would now get something wrong:

1. **Open the index, then every page it links to that covers the affected area.** The index is
   the map; don't guess which pages matter. If it states a charter, that charter wins.
2. **Prefer the smallest edit that restores truth**, in this order: generalize existing wording
   → correct existing wording → add a sentence. **A sync that makes a page longer needs a
   reason you can state out loud.** Generalizing has one limit: when the responsibility itself
   is gone, the page is deleted, not blurred — see [the form of a page](page-form.md).
3. **Apply the [admission test](principles.md) to every sentence you add or keep.** Editing
   around a sentence makes you its author.
4. **Run [the checker](checker.md) on each page you touched.** Fix every ERROR; resolve or
   justify each WARN.
5. **Reflect any page add, rename or removal in the index** in the same change. For a new page
   or a new index entry, follow [the form of a page](page-form.md).

Done when every page you touched matches the code, the checker reports no errors, and the
index links every page that exists.

## Reporting

State what changed and why in one or two sentences: which claim went stale, and the smallest
edit that fixed it. If the gate ended the run, say the docs need no change and name what you
checked — a reader has to be able to disagree with the conclusion.
